# SQL エンジン（go-mysql-server のフォーク）

HeimDB の SQL の構文解析の後ろ（解析、実行計画、実行、MySQL の通信の受け口）は、[go-mysql-server](https://github.com/dolthub/go-mysql-server) をフォークした `internal/sqlengine` が受け持つ（[`plan.md`](plan.md) の段階 40）。この文書は、取り込み元、取り込まなかったもの、変更の一覧、上流の修正を取り込む手順を記録する。

## 取り込み元

| | |
| --- | --- |
| 上流 | `github.com/dolthub/go-mysql-server` |
| バージョン | v0.20.0（コミット `5d7248826`、2025-05-13） |
| 取り込んだ日 | 2026-10-12 |
| ライセンス | Apache License 2.0（`internal/sqlengine/LICENSE`。元の著作権の表示はファイルに残す） |

フォークした理由: 上流はリリースの間隔が長く（v0.20.0 の後、2026-10 の main まで 17 か月、3,442 コミット）、main は正規表現で C のライブラリ（ICU）を既定にした（Go だけで使うにはビルドのタグ `gms_pure_go` が要る）。HeimDB が回避しているセキュリティと panic の問題は main でも直っていない。HeimDB は手を入れたい部分が多く、WordPress への特化も進めたい。

## 取り込まなかったもの

- `sql/encodings`（文字コードの表、約 90MB の生成コード）: 標準ライブラリにしか依存しないので、元のモジュール `github.com/dolthub/go-mysql-server` v0.20.0 からそのまま読む（`go.mod` に残る go-mysql-server への依存は、これのためだけ）。照合順序の重みはインデックスのキー、つまりデータ形式に響くので、上げない（dependabot も上げない）。
- `_example`、`_integration`（他の言語のクライアントの例）、`driver`（`database/sql` のドライバ）: HeimDB は使わない。
- 上流のリポジトリの運営のファイル（`README.md`、`CONTRIBUTING.md`、`MAINTAINERS`、`SECURITY.md`、`SUPPORTED_CLIENTS.md`、`Makefile`、`check_repo.sh`、`format_repo.sh`、`mascot.png`、`go.mod`、`go.sum`）と、開発の道具を依存に入れるだけの `tools.go`。

上流のテスト（`enginetest`、`memory`、各パッケージの `_test.go`）は、エンジンを変えたときの回帰の安全網として取り込んだ。外した機能のテスト（`TestLoadData`、`TestLoadDataErrors`、`TestLoadDataFailing`、`TestSelectIntoFile`）は、外した機能が `sql.ErrServerFiles` になることを確かめる `TestServerFilesRemoved` に置き換え（段階 42）、残っていた本体と期待値は段階 66 で消した。構文解析と通信の vitess（`github.com/dolthub/vitess`）は、バージョンを固定した依存のまま（手を入れるときに同じ形で取り込む）。

- 変更は、この文書の「変更の一覧」に短い行（段階、変えた所と何を変えたか、短い理由）を足し、詳しい変更と理由はその段階の [`stages/`](stages/) のファイルの「エンジンの変更」に書く。記録だけにした MySQL との違いは [`differences.md`](differences.md) に足す。テストを足す（HeimDB の側のテストか、エンジンのテスト）。
- 中身を変えたファイルは、頭の著作権の表示の下に `// Modified by Tsukinowa Inc.: <何を変えたか>（docs/engine.md）` の行を足す。
- 上流のテストが落ちる変更をするときは、テストも直し、理由を書く（WordPress に要らない機能を外すなど）。
- 取り込んだ時点で、上流のテストは 27 のパッケージで 53,301 件が通り、416 件が飛ばされた（v0.20.0 そのままと同じ）。段階 42 の後は 53,208 件が通り、414 件が飛ばされた（外した機能のテストの分）。段階 66 の後は 53,227 件が通り、411 件が飛ばされる（条件なしで飛ばすテスト 3 件を消した）。

## 確かめ方

```sh
go test ./internal/sqlengine/...   # 上流のテスト（パッケージごとに並列。いちばん遅いもので約 30 秒）
go vet $(go list ./... | grep -v internal/sqlengine)
```

`go test` が自動で走らせる `go vet` の確認は、エンジンでも通る（段階 42 で書式の文字列を直した）。`go vet` を全部かけると、エンジンには構造体の書き方などの指摘がまだ 84 件残るので、`go vet` はエンジンを除いてかける。

## 上流の修正を取り込む

1. 上流のリポジトリで、取り込み元のコミット `5d7248826` から取り込みたいコミットまでの差分を取る（`git diff 5d7248826 <commit> -- <path>`）。
2. 差分のパスを `internal/sqlengine/` に、import のパスを書き換えて当てる（`git apply --directory=internal/sqlengine`）。当たらなければ（HeimDB が変えたファイル、上流の大きな書き換えの後のもの）手で移す。同じ箇所の HeimDB の直し（変更の一覧の行）を読み、どちらを残すかを理由とともに書く。
3. 変更の一覧に、上流のコミットとともに書く。取り込みは 1 件 1 コミットにし、コミットを戻すとテストが落ちることを確かめる。
