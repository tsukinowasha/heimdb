# Stage 131: reads do not wait for a backup, and backups inside -data

## Background

Stage 130 recorded two problems ("Only recorded" in [`130.md`](130.md)):

- While a backup to another filesystem held the write lock (11.7 seconds for 2 GB), every page stopped, reads included. An `INSERT` that waited for the lock had already taken an AUTO_INCREMENT value, and a commit with no writes (an autocommit `SELECT` too) tried to save the unsaved value and waited for the same lock.
- The Docker image fixes `-data /data`. A backup volume such as `/backups` is another mount point, hard links do not cross mount points, and every backup copied all files.

## Plan

1. A commit with no writes saves the unsaved AUTO_INCREMENT counters only if the write lock is free.
2. Allow `-backup-dir` inside `-data`, so that with Docker the backups go to `/data/backups` on the data volume and are hard links.
3. Not measured again on GCE (the bench now needs its own project); tests reproduce both cases.

## Changes

- `Txn.Commit` (`internal/store/txn.go`): a commit with no writes calls `tryFlushAutoIncrements` (`autoinc.go`), which does nothing when `writeMu` is held (`TryLock`). The holder, or the next commit, saves the counters (`writeDirtyAutoIncrements` in every `Update`), and `Close` saves them too. If the process dies before that, the counter starts from the largest value in the rows plus 1 (as for any value not saved yet), so a value that no committed row uses may be handed out again; a value in a committed row is never reused. The second half of `updateWaits` became `commitLocked`, used by both.
- `checkBackupDir` (`cmd/heimdb/main.go`): `-backup-dir` equal to `-data` is still refused. Inside `-data`, the name of the directory right under `-data` must have no `.` and must not be `LOCK` or start with `MANIFEST-` or `OPTIONS-`. Pebble skips names that its `base.ParseFilename` does not parse, when it opens the store and when it deletes obsolete files, and a checkpoint links only the store's own files, so a backup does not contain the earlier backups.
- Docs: `operations.md` and `dockerhub.md` use `-backup-dir /data/backups`; the two items are removed from `differences.md`.

## Engine changes

None.

## Tests

- `TestReadOnlyCommitDoesNotWaitForAutoIncrement` (`internal/store`): with `writeMu` held and an unsaved counter, a read-only commit returns at once; with the lock free, it saves the counter, and the value survives a reopen.
- `TestSelectDoesNotWaitBehindInsert` (`internal/backend`): while `Update` holds the write lock, an `INSERT` into `wp_posts` waits, and a `SELECT` on another connection returns. It fails without the change (the `SELECT` waits).
- `TestCheckpointInsideDataDir` (`internal/store`): a checkpoint into `<data>/backups/b1` hard-links the data files; after more writes, a compaction and a reopen, both the store and the backup open with their rows.
- `TestCheckBackupDir` (`cmd/heimdb`): the names allowed and refused.
